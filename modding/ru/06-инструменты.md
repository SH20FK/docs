## Консоль разработчика — F8

Работает и в лаунчере, и в игре. Сама консоль по-английски, как редактор Godot: это инструмент разработчика.

| Команда | Что делает |
|---|---|
| `help` | Все команды (и добавленные модами) |
| `mods` | Установленные моды, включены ли, порядок, у кого есть код |
| `problems` | Всё, что пошло не так при загрузке модов |
| `check [id]` | Проверить один мод или все (см. ниже) |
| `json <путь>` | Итоговые данные после всех правок, например `json res://data/crises.json` |
| `reload` | Сбросить кэш: JSON, тексты, картинки перечитаются при следующем обращении |
| `eval <выражение>` | Выражение с `game` и `Pax`: `eval game.distance_ly("Земля", "Проксима b")` |
| `new <id> [Имя]` | Создать мод из шаблона и открыть его папку |
| `pack <id>` | Упаковать мод-папку в zip в `user://mods_dist/` |
| `folders` | Где ищутся моды |
| `events` | События и решения модов: ● — условия выполнены сейчас; флаги |
| `fire <id>` | Показать событие мода прямо сейчас, не дожидаясь условий |

Свои команды: `Pax.register_command("name", func(args): return "…", "stock_line")`. ↑/↓ — история.

## Проверка

```
godot --headless --path <папка игры> -- --check-mods            # все моды
godot --headless --path <папка игры> -- --check-mods my_mod     # один
```
В выпущенной игре вместо `godot --path …` — `PaxUniverse.exe`. Код выхода `0` — ошибок нет, `1` — есть (для CI).
Проверяется:

- `mod.json`: корректный JSON, формат id, зависимости на месте и нужной версии, версия API и игры.
- Каждый `.json` мода читается (с номером строки ошибки).
- Каждый `data/*.patch.json` относится к существующему файлу игры, применяется, а `$match` что-то находит.
- Замена целых файлов игры (предупреждение — лучше правки).
- Тела после правок: имена, `род`, родители раньше лун, известные системы, наборы текстур, файлы шейдеров и моделей.
- Переводы: во всех `data/lang/*.json` мода одинаковые ключи, английский есть.
- Код: `entry` на месте, начинается с `extends PaxMod`, компилируется.
- Картинка и описание.

Каждое сообщение говорит, что не так, где и как исправить, — и людям, и ИИ-ассистентам.

## Создание и упаковка

```
godot --headless --path <игра> -- --new-mod my_mod Моё название
godot --headless --path <игра> -- --pack-mod my_mod [папка]
```
`--pack-mod` не упакует мод с ошибками. В zip не попадают `.import`, `.uid` и мусор системы.

## Редакторы

- **VS Code:** `.vscode/settings.json` из шаблона подключает JSON-схемы — автодополнение и подсказки для `mod.json`,
  `bodies.patch.json` и переводов. Для GDScript поставьте расширение *godot-tools*.
- **Редактор Godot:** откройте проект игры; папку `mods/` импорт не трогает (`.gdignore`), файлы правьте любым
  редактором и запускайте игру из Godot — моды из `<проект>/mods/` грузятся напрямую, без упаковки.
- **Справочник API** собирается из кода: `python tools/modding/api_reference.py` (исходники игры).

## Студия модов в лаунчере

Лаунчер → **Моды** → **«Создать свой мод»**. Слева файлы, в центре код, внизу настоящий терминал.

- **Мастер** предлагает начать с пустого мода, планеты, звёздной системы или **событий и решений** — копии живого примера под вашим id.
- **＋ Событие** — конструктор: заголовок и текст на двух языках, условия, шанс, варианты с эффектами или решение с ценой и откатом. Запись дописывается в `data/mod_events.patch.json`, файл открывается рядом — его можно доправить руками.
- **✨ Опиши словами** — пишете, что хотите, выбираете агента (Makura, Claude Code, Codex). Студия кладёт в папку мода `ЗАДАНИЕ_ИИ.md` с вашим текстом и правилами и запускает агента в терминале с командой прочитать его.
- **✔ Проверить** — отчёт проверки, где имена файлов — ссылки: щелчок открывает файл на строке с ошибкой.
- **▶ Играть с модом** — игра с включённым модом; F8 → `events`, `fire <id>` проверяют события без ожидания.

## ИИ-ассистенты

В шаблоне есть **`AGENTS.md`** — инструкция, которую читают Claude Code, Cursor, Copilot, Codex и другие, — и
`CLAUDE.md`, который ссылается на неё. Там: где что лежит, правила (правка вместо копии, русские ключи данных,
тексты в `data/lang`, строгие типы) и обязательный запуск проверки. Хороший порядок работы:

1. `new my_mod` → откройте папку игры в редакторе или ассистенте (чтобы он видел `data/` и `docs/`).
2. Опишите мод простыми словами. Для большого мода сначала попросите план.
3. Пусть ассистент запускает `--check-mods my_mod` и исправляет найденное.
4. Запустите игру, F8, `problems`; посмотрите результат глазами.

## Страница автора и «Поддержать автора»

Имя автора в карточке товара — ссылка: по ней игрок видит все ваши моды и пресеты и сводку — сколько установок,
средняя оценка, голоса этого месяца, сколько работ проверено на текущей версии.

В кабинете автора на сайте (правка товара) есть два необязательных поля: ссылка на ваш **Boosty** и на ваш **Patreon**.
Заполните — и в карточке товара и на вашей странице появятся кнопки «Поддержать автора». Принимаются только адреса
`https://boosty.to/…` и `https://www.patreon.com/…`. Это ваши личные сборы: игра в них не участвует и комиссию не берёт.
Обновление версии из студии эти ссылки не трогает.

## Вестник моддера: мод месяца и джем одного заголовка

Каждый месяц в шапке магазина выходит газетный лист с одним **заголовком из будущего** — например, «Луна объявила
независимость». Это и есть тема джема.

- **Джем.** До 10-го числа выложите мод или пресет, в котором такой заголовок может случиться, и добавьте ему метку
  `jam-ГГГГ-ММ` (например `jam-2026-10`). Кнопка «Участвовать» на листе открывает студию и кладёт метку в буфер обмена.
  Проще всего — событие или решение из [главы 7](07-события-и-решения.md): кода не нужно.
- **Мод месяца.** Участвует весь каталог, метка не нужна.
- **Голоса.** Игроки голосуют в лаунчере, в карточке товара, и только за то, что у них установлено: один голос за мод
  месяца и один — за работу по заголовку. До конца месяца голос можно отдать другому. За своё голосовать нельзя.
- **Победа.** Больше всех голосов, но не меньше трёх; при равенстве решает число установок. Победители весь следующий
  месяц стоят первыми в каталоге со значком 🏆 или 📰, автор получает роль «Моддер месяца» в Discord и три ключа игры
  в подарок кому угодно. Итоги — первого числа, время московское.

Отметка **✔ «Проверено на этой версии»** — не награда: её ставим мы, когда мод прошёл проверку на текущей версии игры.

## Если что-то не так

| Признак | Причина / решение |
|---|---|
| Мода нет в лаунчере | Нет или сломан `mod.json`; имя папки начинается с `_`/`.`; zip без `mod.json`. Почему — покажет `problems`. |
| Изменения не видны | После правки JSON — `reload` или перезапуск; порядок загрузки (позже — главнее). |
| `$edit found nothing matching …` | В `$match` не тот ключ или значение (точное русское имя, например `"Марс"`). Посмотрите `json <путь>`. |
| Скрипт «does not compile» | Строка — в выводе Godot. Чаще всего `var x :=` из нетипизированного значения → укажите тип. |
| Нет текстуры | `"map"` — путь **без** `_albedo.png`; файлы называются `<имя>_albedo.png`. |
| Планета не там | `a` — в км; лунам нужен `"period"`; родитель должен стоять раньше луны. |
| Вместо текста ключ | Ключа нет ни в `data/lang/<код>.json` языка игрока, ни в `en.json`. |
