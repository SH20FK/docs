# 09. Воксели: разрушаемые миры и модели из данных

Игра сама вокселей не использует — это набор инструментов для модов. На нём можно сделать разрушаемые планеты,
воксельную копию Земли с провинциями, станции и корабли без 3D-редактора, а то и свою игру поверх Pax Universe.
Всё доступно через `Pax.voxel`. Полный список функций — в [справочнике API](../en/api-reference.md), раздел PaxVoxel.
Живой пример — заготовка **«🧊 Воксельный мир»** в студии (мод `example_voxel`).

## Подключение

В `mod.json` добавьте:

```json
"components": ["voxel"]
```

Лаунчер сам докачает библиотеку [Voxel Tools](https://github.com/Zylann/godot_voxel) (Marc Gilleron, MIT, около
10 МБ), а игра подключит её **до** загрузки вашего кода — поэтому в скриптах можно писать классы библиотеки по имени:
`VoxelLodTerrain`, `VoxelBuffer`, `VoxelTool`, `VoxelGeneratorGraph` и остальные. Мод без компонента тоже может строить
модели из данных (см. ниже) — для них библиотека не нужна.

## Модели из данных

Станция, корабль, здание — это JSON, а не файл из Blender. Игра превращает его в сетку.

```json
{
  "size": [36, 14, 36],
  "palette": ["#d8dce4", "#f2b33d", "#5b7fc7"],
  "shapes": [
    {"type": "torus", "center": [18, 7, 18], "radius": 14, "tube": 1.8, "color": 1},
    {"type": "cylinder", "center": [18, 7, 18], "radius": 2.6, "height": 12, "color": 2},
    {"type": "line", "from": [4, 7, 18], "to": [32, 7, 18], "width": 1, "color": 3}
  ],
  "voxels": [[18, 0, 18, 2]]
}
```

```gdscript
var станция: MeshInstance3D = Pax.voxel.model(JSON.parse_string(read_text("models/station.json")))
```

Фигуры: `box` (from, to), `sphere`, `cylinder`, `torus` (center, radius, tube, axis), `line` (from, to, width).
`color` — номер цвета в палитре с единицы, `0` вырезает. До 96 кубиков по стороне. Такой JSON хорошо пишет нейросеть:
попросите в терминале студии «сделай воксельную модель орбитальной верфи в формате models/station.json».

## Воксельная планета

```gdscript
var планета := Pax.voxel.planet({"radius": 300, "relief": 24, "editable": true})
мир.add_child(планета)
Pax.voxel.viewer(камера)          # без «зрителя» воксельный мир не грузится
Pax.voxel.dig(планета, точка, 20) # кратер
Pax.voxel.fill(планета, точка, 10) # насыпь
var удар := Pax.voxel.raycast(планета, откуда, направление)  # {position, normal, distance}
```

Параметры: `radius`, `relief` (высота гор), `noise` ({seed, frequency, octaves}), `heightmap` (своя карта высот 2:1),
`lods` (уровни детализации), `editable` (можно ли копать), `color` или `material`, `collisions`.

## Копия планеты игры с провинциями

```gdscript
var земля := Pax.voxel.body_planet(game.home_body(), {"radius": 200, "editable": true})
```

Рельеф — по картам тела (суша выше моря, светлее — выше), цвета — его снимок, поверх — **провинции в цветах
владельцев**: те же данные, что у карты игры. Поэтому пресеты и сценарии, размеченные в редакторе пресетов, картой
из картинки, из Azgaar или кистью планеты, сразу выглядят правильно и на воксельном мире.

- `Pax.voxel.province_at(тело, точка)` — какая провинция под точкой воксельной планеты;
- `Pax.voxel.province_position(тело, id, радиус)` — точка над центром провинции (поставить город, подпись, камеру);
- `Pax.voxel.refresh_provinces(земля.material)` — перекрасить после смены владельцев (удобно в хуке `province_captured`);
- `Pax.voxel.place(земля, transform)` — двигать и вращать планету так, чтобы карта не «съезжала».

Провинции теперь открыты и в `Pax.game`: `province_count`, `province_at`, `province`, `province_owner`,
`set_province_owner`, `provinces_of`, `province_direction` — для любого тела.

## Сценарии

Сценарий с вокселями собирается из тех же кирпичей, что и обычный:

1. **Карта и страны** — пресет (редактор пресетов, [08 Своя карта](08-своя-карта.md)).
2. **Сюжет** — события и решения без кода ([07](07-события-и-решения.md)). Для вокселей есть два эффекта:
   - `"кратер": {"province": 1368, "radius": 300}` — удар по провинции на всех воксельных копиях тела; вместо номера
     можно `"случайная"` или название страны (тогда — её случайная провинция), радиус — в километрах настоящей планеты;
   - `"province": {"id": "Франция", "owner": ""}` — сменить хозяина провинции (тоже номер, `"случайная"` или страна).
3. **Вид** — воксельная копия планеты в окне мода или на месте тела.

В примере `example_voxel` есть событие «Метеорит»: кратер в случайной провинции и запись в хронику.

## Что важно знать

- **Сохранение.** Игра не хранит воксельные миры. Записывайте, что копали, и повторяйте после загрузки через
  `_save_state` / `_game_loaded` — так сделано в примере.
- **Файлы.** Классы библиотеки, которые пишут на диск (`VoxelStream…`, `VoxelVoxLoader`, `debug_dump_as_scene`,
  `save_modified_blocks`), модам закрыты: сторож их не пропустит.
- **Сеть.** Мод с вокселями должен стоять у всех игроков партии. Если он только показывает картинку и не меняет правила,
  поставьте в `mod.json` `"client_only": true`.
- **Производительность.** Генерация, сетка и уровни детализации считаются библиотекой на C++ в фоновых потоках.
  Планета радиусом 200–300 вокселей грузится за несколько секунд. Для копания поставьте `"editable": true` — тогда
  планета загружается целиком, это дороже по памяти.
- **Что не рисуется.** Куски вне камеры, внутренности планеты и скрытые грани кубиков не рисуются никогда. Обратную
  сторону планеты отсекает невидимый шар внутри неё (`planet()` ставит его сам, `"occlusion": false` — убрать):
  у поверхности это минус четверть кусков. Работает в основном окне игры — `viewer()` включает отсечение сам;
  в окне-вставке (SubViewport) Godot отсечение по перекрытию не выполняет.
- **Модели.** Когда компонент стоит, модели из JSON собирает построитель библиотеки на C++ и склеивает соседние
  грани одного цвета: у станции из примера вершин втрое меньше.
